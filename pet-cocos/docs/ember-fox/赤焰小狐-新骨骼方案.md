# 赤焰小狐 · 新骨骼方案（ember-1.0）

预览：`ember-fox-preview.mp4`（待机 / 侧走 / 背走 / 朝镜头走 / 攻击 / 开心 / 受击 / 睡觉）。

## 为什么不再从一张原画里切

旧流程是"先有一张完整立绘，再用脚本把它切成胸、腿、手臂，补网格去拉"。问题出在根上：

- 立绘里被挡住的部分（腿根、肩膀、手臂后面）根本没有画，只能靠拉伸和补边，动起来必然露缝。
- 立绘是摆好战斗姿势的正面像，膝盖、肩膀的位置不是为关节设计的，转动中心找不对。
- 每修一处缝，就要在注册坐标、逆绑定矩阵上再叠一层补丁，越修越乱。

## 新方式：先设计"可动的拆件"，再绑定

所有部件在同一张 1000×1000 画布、同一个坐标系里**分层绘制**（相当于一份分好层的 PSD），关节在设计时就藏好：

| 关节 | 怎么藏 |
|---|---|
| 肩 | 手臂是两端圆头的胶囊，绕圆心转动，圆转到哪都还是圆 |
| 胯/腿 | 腿上端画进身体下面；腿是"髋骨→脚骨"两骨网格，身体起伏时腿自然伸缩 |
| 耳朵 | 耳根画在头的后面，转动时被头盖住 |
| 脖子 | 围巾正好包住头和身体的接缝 |
| 尾巴、围巾尾 | 一整块网格，沿 3~4 根骨骼平滑弯曲，没有分段 |

正面和背面各自有身体、头、耳朵、围巾的图；手臂、腿、尾巴、剑两面共用。尾巴在背面视图里换到身体前面的插槽（`tail-front`），不需要动画里改绘制顺序。

## 动作

所有动作都在 `tools/ember-fox/anims.mjs` 里，以"时间→姿势"函数写成，再采样成 Spine 时间轴：

- 走路 0.6 秒一循环，支撑脚按地速后移（与 `ChibiWalk.ts` 的步幅一致，不滑步）；身体每步一沉一弹，头、耳、尾巴、围巾依次滞后。
- 背走、朝镜头走：脚沿纵深上下移动，离镜头近的脚自动画在前面。
- 攻击：下压蓄力 → 上挑挥剑 → 火焰刀光 → 定格 → 收势；`strike` 事件在 0.29 秒，只触发一次。
- 待机（呼吸、耳朵抖动）、开心（两次小跳）、受击、嗅闻、睡觉、醒来、起步/停步。
- 表情（第 1 轨）：calm / focus / happy / alert / sleep，带自动眨眼；视线（第 2 轨）：look-left/right/center。

## 接入

- 资源：`assets/resources/forest/ember/`（ember.json / .atlas / .png，Spine 4.2）。
- 运行时约定：`assets/scripts/EmberRig.ts`（自动生成）。
- 切换：`assets/scripts/ActiveRig.ts` 一处决定场景用哪套骨骼；改回旧狐狸只需按文件里的注释换两行。
- 重新生成：`npm i` 后 `npm run ember:build`。
- 测试：`tests/ember-fox.test.mjs`。

## 说明与下一步

- 这一版的美术是我用代码画的矢量分层图，风格是"粗黑描边 + 平涂 + 少量排线"，细节比原来的 AI 立绘少。重点是**拆件结构和绑定方式**是对的。
- 想要更精细的画面：保持每个部件的画布位置和转轴不变，让画师（或出图工具）按图层逐个重画，替换 `parts.mjs` 里对应部件即可，骨骼和动作都不用改。
- 其他宠物可以沿用同一套骨骼与动作，只换部件图。
- 改动前的脚本备份在 `.backup-before-ember/`。
