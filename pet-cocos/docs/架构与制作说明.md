# 从参考架构到单宠实现

## 检查结论

对用户指定的《咩咩启示录》构建完成只读 REA MCP 与补充静态解析。确认 Unity 2022.3、spine-unity、主角 Spine 3.8.99 骨架数据，以及面向相机、方向动画、混合、事件转发和阴影处理相关代码。完整证据链及适用范围见同目录《咩咩启示录架构分析》。原始证据文件保存在工作区 `outputs/cult-lamb-rea-20261024`，本交付不捆绑原作文件。

开发商说明与检查相互支持：[Massive Monster 的开发者回复](https://steamcommunity.com/app/1313140/discussions/0/3448087385671383167/?l=english)描述2D绘画、3D摆放和Spine网格变形；[Unity 官方采访](https://unity.com/blog/games/recipe-behind-smash-hit-cult-of-the-lamb)描述2.5D、精灵组合和定制灯光。Unity 这篇采访本身没有明确写 Spine。

## 本工程的选择

```text
GameModel 资源与存档 ← PetGame 训练/实时战斗 → PetBrain 状态与移动
                              ↓                    ↓
                         GameUI/PaperUI        PetView 原生Spine
                              ↑                    ↓
                           WorldScene ← 透明RenderTexture
                              ↓
                 3D地面坐标 + 相机对齐平面 + 接触阴影
                              ↓
                   世界RenderTexture → 竖屏Cocos UI
```

Spine 首先由 Cocos 原生组件绘制到800×800透明纹理，再交给3D平面显示。这样保留原生骨骼、加权网格和动画事件，也能在宠物详情复用同一个动态形象。场景再绘制为720×648（营地）或720×954（战斗）纹理，以适配竖屏UI。这里多了一次离屏渲染，移动端要测量 GPU 开销；大量宠物时应考虑共享材质、更新裁剪或直接世界空间渲染，不宜每只都无条件建立独立高分辨率纹理。

3D物体使用透明边缘裁切和深度写入；阴影位于地面，跟随角色位置。原作使用自己的坐标约定，本工程地面选择XZ，与其代码里将z置零的做法并不相同。

攻击由状态机启动，Spine 时间线在0.29秒触发 `strike`。当前攻击编号只允许结算一次；受击打断后，旧攻击不能继续造成伤害。脚步事件触发尘土，完成事件让非循环动作回到待机。逻辑不依赖用CSS缩放图片来模拟骨骼。

## 单宠制作规格

| 项目 | 当前值 |
| --- | --- |
| 宠物 | 赤焰小狐 / 近战战士 |
| Spine版本 | 4.2，使用Creator的spine-4.2模块 |
| 骨骼 | 21 |
| 插槽 | 9 |
| 加权网格附件 | 9；每个网格121顶点、200三角形 |
| 主动作 | idle / walk / attack / hit / happy |
| 额外轨道 | 自动眨眼、专注、开心等表情 |
| 表情实现 | 头部图片切换；耳朵另外以权重骨骼变形 |
| 绑定原始资料 | source-assets/fox-v1 与 tools/build-fox.mjs |

为了控制首版成本，左右朝向使用镜像，当前没有独立背面动画。营地建筑仍保留在绘画中，交互靶、箱子、核心、怪物与狐狸才是独立对象。下一阶段可先拆树冠/草地/旗帜并制作局部摆动，再增加受光、角色方向和更细的动作节奏。
